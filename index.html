01

Humanoid locomotion

G1 Robust Locomotion

public Unitree G1 · 23-DoF PPO / RSL-RL MuJoCo Warp · mjlab trained from scratch

Stand, walk forward and backward, run, and take hits from any direction — trained from scratch, no pretrained policy and no imitation data. Robustness comes from two different disturbances, not one: instantaneous push impulses, and a sustained random-heading drag that holds force for seconds and keeps stealing momentum. A shove and a drag fail a policy in different ways, so each gets its own curriculum, layered over a three-stage command-envelope curriculum so difficulty rises on two axes at once.

Anti-reward-hacking is a design axis. Every gait reward ships alongside the term that closes its exploit — marching in place, foot sliding, hard landings, posture drift. When the policy failed backward pushes, it got a dedicated isolation run and a targeted curriculum fix before any retraining: debugging a policy like a system rather than a slot machine. Trained end-to-end on 2×T4 with a checkpoint/resume harness that survives 9–12 h session kills.

A delta only means something when it clears both its own spread and the class's per-image quantum (1/support). Held to that rule, the honest summary of this experiment is: no macro effect, one small real on-target gain, one small real on-target loss, and a large off-target gain with a mundane explanation.

Melanoma sensitivity is the clinically critical metric in this domain, and +0.116 would have been the headline. The writeup declines to claim it, names the confound, and specifies the balance-matched control (oversampling real rare classes) needed to separate a rebalancing effect from a realism effect. The generation side is built to the same standard: every synthetic image passes memorisation gates before it may be used, and each one is tracked in a provenance manifest flagged synthetic: true.

data-doctor

on PyPI Python · Pillow only CI-gated MIT

A 10-second habit instead of a post-mortem: exact duplicates, near-duplicates, train/val leakage and COCO structural defects (duplicate ids, annotations referencing missing images, degenerate boxes and polygons, zero-annotation images) in one command. Exit code 1 on failure, so it drops straight into CI. Rotated, flipped, re-encoded and resized copies are caught, and the hash distance sets how much recompression it tolerates.

EasyAnnotate

product source private annotate · convert · clean · split · augment VOC · YOLO · COCO · LabelMe · CSV CLI · web · desktop · Docker

The whole dataset workflow in one tool: annotate, import a model's predictions and correct them, convert between formats, deduplicate, split without leakage, resize, tile, augment, and report. One rule decides what ships: if a feature needs configuring before you can draw the first box, it does not ship. Mainstream annotation tools ask for an organisation, a project, a label schema and a task first. Here a class is created by drawing a box and typing its name.

The model loop. Annotate a few hundred images, train, then load the model's predictions back in — YOLO, VOC, LabelMe, COCO, or the bare detection-results list that evaluation scripts emit. Predictions render dashed and fade with confidence; one key accepts what is visible and moves on. Every import reports what did not match, because a file-name mismatch that imports zero shapes looks exactly like a model that predicted nothing. Export takes reviewed images only by default: feeding a model its own unchecked predictions as ground truth is how it poisons itself, and nothing in the output looks wrong when it happens.

Model agreement tells you when to retrain and when to stop. It counts only images a person has reviewed, and it counts deletions, since deleting a false positive is the commonest correction there is. Segmentation models such as SAM propose outlines from a separate process, so an out-of-memory crash takes the tool down, not the editor, and masks are simplified to editable polygons with a vertex cap rather than thousand-point outlines. Existing folders can be annotated in place, writing back to their own VOC, LabelMe or YOLO files atomically.

KrishiDisha — a grounded agricultural assistant, not a chatbot with a crop model bolted on

IEEE 2025 first author Flask · SQLAlchemy 13-tool LLM loop offline fallback 150+ farmers

First-author work published at IEEE ICoEIT 2025 (pp. 1028–1040), and still under active development. Eight services sit behind one advisory surface: crop recommendation (22 crops from an N-P-K and climate soil test, top-3 with probabilities and indicative economics), fertilizer recommendation with a kg-and-bags dose calculator and split schedule, leaf-photo disease detection across 38 PlantVillage classes with prevention steps, yield prediction for 55 crops × 30 states × 6 seasons, weather advisories from Open-Meteo (spraying windows, frost and heat warnings, soil moisture), live mandi prices from data.gov.in’s Agmarknet feed with an MSP fallback, 16 central government schemes with eligibility and application steps alongside 32 crop guides and a sowing calendar, and a marketplace of 60 farm inputs with cart, COD/UPI checkout, stock control and order tracking. Every recommendation emits a PDF the farmer can carry to a dealer.

Model selection was run as a comparison, not a single fit. Seven classifiers (Random Forest, Gradient Boosting, XGBoost, SVM, kNN, Decision Tree, GaussianNB) were evaluated under 5-fold CV with a fixed seed and a held-out test split: crop recommendation went to GaussianNB at 99.5% test accuracy (macro-F1 0.995, CV 0.995 ± 0.004) over Random Forest’s 99.3%, fertilizer to XGBoost, and yield to XGBoost at test R² 0.94 (CV 0.964 ± 0.028). Full per-class reports and evaluation plots are committed alongside the metrics file, and python -m ml.train_all reproduces the whole thing.

It degrades instead of breaking. The rules provider is a complete offline intent engine that still runs the ML models, the weather and price lookups, the dose calculator, the scheme database and knowledge search — so with no API key, no credit and no connectivity to a model vendor, the assistant keeps answering. That matters more than benchmark accuracy for the users this targets. Field-validated with 150+ farmers on real plots; the test suite runs fully offline against an in-memory database.

In progress: a small in-house language model trained on the project’s own agronomy corpus, to replace the hosted providers entirely and run the assistant on commodity hardware.
